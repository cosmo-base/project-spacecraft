# プレイデータを Google スプレッドシートに記録する設定

ゲームは、エンディングに着いたときのプレイ結果（選択の記録・数値の変化・ミッションレポートなど、プレイを再現できる情報）と、ご意見欄の内容を、Google Apps Script 経由でスプレッドシートに送ります。
同意した参加者のデータだけが送られます（同意しないとゲームは遊べません）。

## 1. スプレッドシートを用意する

1. 運営用の Google アカウントで、新しいスプレッドシートを作る（例：「宇宙機シミュレーター プレイデータ」）
2. 共有設定は **運営の担当者だけ** にする（「リンクを知っている全員」にはしない）

## 2. スクリプトを貼り付ける

1. スプレッドシートのメニュー「拡張機能 → Apps Script」を開く
2. 最初からある `コード.gs` の中身をすべて消し、このフォルダの [`Code.gs`](Code.gs) の中身を貼り付けて保存する

シート `play`（プレイ結果）と `feedback`（ご意見）は、最初のデータが届いたときに自動で作られます。

## 3. ウェブアプリとしてデプロイする

1. 右上の「デプロイ → 新しいデプロイ」
2. 種類の選択で「ウェブアプリ」
3. 次のように設定して「デプロイ」
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**（ゲームを遊ぶ人がログインせずに送れるようにするため）
4. 初回は権限の確認が出るので、運営アカウントで許可する
5. 表示された **ウェブアプリの URL**（`https://script.google.com/macros/s/…/exec`）をコピーする

URL をブラウザで開いて `{"ok":true,...}` と表示されれば受け口は動いています。

## 4. ゲームに送信先を設定する

**GitHub Pages で公開する場合**：リポジトリの Settings → Secrets and variables → Actions → **Secrets** に、`ANALYTICS_ENDPOINT` という名前でウェブアプリの URL を登録します。push すると、自動ビルドのときに組み込まれます。

**手元でビルドする場合**：プロジェクト直下に `.env.local` を作り、コピーした URL を書きます（`.env.example` を参考に）。

```
VITE_ANALYTICS_ENDPOINT=https://script.google.com/macros/s/XXXXXXXX/exec
```

その後ビルドし直すと、送信先が組み込まれます。

```bash
npm run build
```

`.env.local` を作らずにビルドした場合は送信先が空になり、データはどこにも送られません（開発・確認用）。

## 記録される列

**play シート**

| 列 | 内容 |
|---|---|
| receivedAt | 受信日時 |
| playId | プレイごとの使い捨てID（人や端末を識別しない） |
| appVersion | ゲームのバージョン（再現に必要） |
| mode | beginner / expert |
| seed | 乱数のシード（再現に必要） |
| ending / endingTitle | エンディングの種類と名前 |
| phaseReached | たどり着いたフェーズ番号 |
| progress / progressBand | 最終的な達成度と、その帯（20%刻み） |
| design | 選んだ機体構成（JSON） |
| choiceCount / choiceIds | 選択の数と「イベントID:選択肢ID」の並び（再現に必要） |
| finalValues | 最後の数値すべて：資金・期間・信頼性・各マージン・不具合数など（JSON） |
| flags | プレイ中に立ったフラグ（どの分岐を通ったか） |
| log | 選択ごとの数値の変化と、確率判定の見込み・結果（JSON） |
| reportText | 画面に出たミッションレポートの文章 |
| report | ミッションレポートの中身すべて（成果・トラブル・ヒント・選択の記録、JSON） |

**feedback シート**：receivedAt / playId / appVersion / feedback（ご意見、1,000文字まで）

ご意見の送信では、ご意見と playId だけを送ります。同じ playId の play シートの行をたどると、どのプレイへのご意見か分かります。

## プレイを再現する

play シートの `mode`・`seed`・`design`・`choiceIds` があれば、同じ展開を再現できます（バグ調査やバランス調整に使えます）。
**`appVersion` と同じバージョンのゲームのコード**で、`src/engine/replay.ts` の `replayPlay` に渡してください。イベントや数値を変更したあとのコードでは、途中で食い違うことがあります（食い違うと、何手目で食い違ったかをエラーで知らせます）。

そのため、イベントや数値を変えて公開し直すときは、`src/engine/analytics.ts` の `APP_VERSION` を上げてください。

## 運用上の注意

- **保存期間**：コンテンツの提供を終了してから半年以内に削除します。スクリプトエディタで `deleteAllData` を実行すると全行を消せます。スプレッドシートの版の履歴にも残るので、最終的にはファイル自体を削除してください。
- **ご意見欄の個人情報**：注意書きがあっても、個人情報が書かれることはあります。見つけたら該当の行を削除してください。閲覧できる担当者は限定してください。
- **URL は誰でも送信できる**：ウェブアプリの URL は公開ページに組み込まれるため、第三者が直接データを送ることもできます。スクリプトで形式チェックと長さ制限はしていますが、集計の前に明らかに不正な行は除いてください。
- **スクリプトを書き換えたら**、「デプロイ → デプロイを管理」から同じデプロイの新しいバージョンを作ってください（URL が変わりません）。
